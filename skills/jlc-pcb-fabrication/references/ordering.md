# 采购与网页操作

## 裸板、SMT 和散件是三种不同状态

先查已有订单/草稿，核对修订号、文件名、数量和工艺，避免恢复旧稿或重复购买。结构化选项、真实订单状态与备注中的历史意向冲突时，查明当前用户选择，必要时说明旧备注；不因旧“拟做 SMT”文字恢复已放弃的装配流程。

裸板核对外形、层数、厚度、铜厚、阻焊/丝印、表面处理、过孔、板边/拼板、数量、交期、生产稿确认方式，以及确认稿、不加客编、保险/赔付、钢网等附加费。早先项目选过的服务不自动成为下一项目默认值；按用户预算和现有选择准备，超出授权的费用应列出待决定。

工厂装配要分别核对 SMT 与插件、单/双面、元件库类型、损耗、钢网、换料、治具、工程和个性化服务费。不要为了降价虚报贴插间距。单板 BOM 数量、工厂含损耗数量、零售最小包装是不同口径。

用户转手焊时，核对“是否需要 SMT：不需要”；另购原 BOM 散件，寄到用户地址而非自动加入 SMT 私有库。先确定旧 SMT 只是缓存还是已生效订单，不能凭页面存在就取消订单，也不能将保存配单称为已采购。

## 散件数量和价格

按料号匹配并逐项核对厂商型号、封装、参数、位号和每板用量。自动匹配率不证明替代料可用；待确认项核实原料号及数量后再确认。发布版替代料只有在封装/脚序/电气和用户范围均允许时才能采用。

对每种料分别查最小起订量 MOQ 和递增步长/包装倍数。页面“3000/盘”不必然表示最少买一整盘。总需=单板用量×计划装配数＋约定备件；先扣除已确认可用于本项目的合格库存和已付款待到货数量，得到净缺口 N。N≤0则无需新购；N>0且网站明确必须按 P 的倍数购买时，新购总量为 P×ceil(max(N,MOQ)/P)。如果步长从 MOQ 起算或可拆包装，以实际规则为准。核对购物车已有数量，将其调整到所需新购总量，不能把该总量再次追加一遍；未付款购物车不计为已采购。

用户明确“按最小包装”，或已允许小规格阻容因包装多买时，按满足净缺口的最小合法采购量执行，不反复询问；主动超出包装需要囤货仍须有数量/预算依据。计算齐套数：每种料 floor(可用数量/单板用量)，取最小值，并说明是已到手齐套还是全部到货后的齐套。5块裸板配每板需2只、总共只有5只的连接器，只能装2块完整板；不要误报5套。

价格记录以已完成订单为准：商品合计＋运费＋其他收费－优惠/减免。BOM云表、购物车、未填地址的结算页、实付订单可能不同；地址未选时显示运费0、重量0不能说明包邮。不擅自购买会员、凑单或升级快递来获得优惠。

## 网页推进与恢复

优先使用已登录会话和当前可见页面。每次导航、修改或导入后读取最新状态再决定下一步；属性面板经常重建节点，不沿用旧索引。异步页面首次空白/显示未登录时，待正常加载后检查一次，再决定是否确实需要登录。

扩展断连时先重新发现标签，或使用当前工具支持的同浏览器原生界面；不要靠反复刷新丢失编辑。重复动作无效时先查看错误、弹窗或新开的标签，改变有依据的路径。不要猜隐藏接口、沿用过期支付 URL 或读取网页内部应用状态来绕过界面。

阶段结束保留原生备份、当前修订、稳定入口和尚缺事项。记录“已保存配单”“已加入购物车”“已提交”“已付款”等明确状态。标签 ID 仅供当前会话定位，不写进可复用 skill 或项目长期入口。按工具规则保留实际交付页/待用户操作页，不保留无关研究标签。

收货人、联系人、开票资料在 PCB 与商城之间可能不互通。缺资料时让用户在对应网页填写；不要未经授权跨商家复制私密信息。账号归属变更等超出单笔订单的操作单独处理，不由任务推导额外授权。

“准备订单”做到可审阅的文件、物料、数量、工艺和价格，再交接提交/付款；用户明确授权的动作在工具允许范围内继续。接受协议、付款、发消息遵循当前权限要求，不重复询问已有授权的普通步骤。用户报告已下单后只读核对订单和实付，更新状态，不能再次点击购买。

已下单不等于已投产：工程制作、生产稿、生产、出库、发货分别查看。“取货员取货中”表示仓库拣料；订单表的“实发数量”也不单独证明快递已寄出。
